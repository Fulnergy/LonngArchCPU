### 🧱 模块划分清单（基于方案一）

整个设计依然围绕经典的5级流水线（取指、译码、发射、执行、写回）展开，但**发射逻辑（Issue Logic）** 是绝对的大脑和核心。

#### 1. 前端：取指与译码 (Fetch & Decode)

| 模块名 | 功能 | 关键设计点 | 与动态发射的关系 |
| :--- | :--- | :--- | :--- |
| **`IF_stage`** (取指) | 根据PC，从ICache中**一次读取2条指令**（64位）。 | 处理分支跳转、PC生成。 | 为发射逻辑提供“弹药”，确保每个周期都能供应2条新指令。 |
| **`ID_stage`** (译码) | 将取回的2条指令并行译码，识别类型（ALU、LS、Branch等），并读取寄存器堆。 | 支持**双读**（同时为两条指令读源操作数）。 | **关键**：解码后的**指令类型信息（`inst0_type`, `inst1_type`）** 是发射逻辑做决策的核心依据。 |

#### 2. 控制中枢：发射逻辑 (Issue Logic) —— **这是本次设计的核心**

| 模块名 | 功能 | 关键设计点 | 与动态发射的关系 |
| :--- | :--- | :--- | :--- |
| **`Issue_Logic`** | 分析译码阶段的两条指令，**动态决定**如何将它们分配到两个固定通道。 | 1. **冒险检测**：判断两条指令间是否有数据依赖（RAW）。<br>2. **动态分配**：根据指令类型决定发射方案。<br>   - 若`inst0`是ALU，`inst1`是LS，双发射。<br>   - 若**两条都是ALU且无依赖**，**将`inst1`也发射到LS通道**。<br>   - 若`inst0`是LS，`inst1`是ALU且无依赖，**颠倒顺序发射**。<br>3. 生成`issue_ena[1:0]`（发射使能）。 | **这个模块实现了你方案一的全部策略。** 它的输出直接决定了每个周期的发射效率。 |

#### 3. 执行单元 (Execution Unit)

| 模块名 | 功能 | 关键设计点 | 与动态发射的关系 |
| :--- | :--- | :--- | :--- |
| **`EX_ALU`** (ALU/Branch通道) | 固定执行所有ALU运算和分支指令。 | 包含ALU计算单元、分支判断逻辑。 | 接收来自`Issue_Logic`的动态分配。可能执行原指令0或指令1（如果被重排）。 |
| **`EX_LS`** (Load/Store通道) | 固定执行所有访存指令（地址计算），**并扩展执行动态分配来的ALU指令**。 | **关键修改**：除了地址加法器，需**新增一个完整的ALU**（加减法、移位、逻辑），专门用于执行被调度来的第二条ALU指令。 | **这是动态发射的硬件基础。** 让LS通道在空闲时能处理ALU指令，是提升性能的关键。 |

#### 4. 访存与写回 (Memory & Write-back)

| 模块名 | 功能 | 关键设计点 | 与动态发射的关系 |
| :--- | :--- | :--- | :--- |
| **`MEM_stage`** (访存) | 根据`EX_LS`传来的地址，对DCache进行读写。 | 处理Load/Store指令的访存延迟。 | 无直接关系，但需确保能处理来自两个通道的数据。 |
| **`WB_stage`** (写回) | 将结果写回寄存器堆。 | **支持双写回**：两个通道可能同时完成。 | 无直接关系，但寄存器堆需支持两个写端口。 |

#### 5. 存储子系统 (Memory Subsystem) —— 运行Linux的关键

| 模块名 | 功能 | 关键设计点 |
| :--- | :--- | :--- |
| **`ICache`** (指令缓存) | 缓存指令，加速取指。 | 容量、相联度、替换策略。 |
| **`DCache`** (数据缓存) | 缓存数据，加速访存。 | 写策略（写回/写直达）。 |
| **`MMU/TLB`** (内存管理单元) | 虚拟地址到物理地址的转换。 | **这是运行Linux的必备模块。** 实现TLB，处理缺页异常。 |

#### 6. 协同控制与调试 (Control & Debug)

| 模块名 | 功能 | 关键设计点 |
| :--- | :--- | :--- |
| **`Branch_Predictor`** | 预测分支方向和目标地址。 | 实现简单的2-bit饱和计数器预测器。 |
| **`Pipeline_Control`** | 全局流水线控制。 | **生成Stall和Flush信号**，协调IF、ID、EX三个阶段。 |
| **`CSR`** (控制状态寄存器) | 实现LoongArch的特权寄存器。 | 处理中断、异常，保存处理器状态。 |

### 💎 总结：你的行动路线图

1.  **先搭建骨架**：按照上述模块划分，写出顶层`dual_issue_core.v`，例化所有模块，并定义好模块间的接口信号（特别是`Issue_Logic`输出的发射使能信号）。
2.  **重点攻克`Issue_Logic`**：花最多时间在这个模块上。它的正确性决定了整个设计的成败。先实现“静态双发射”，验证通过后，再一步步加入“动态调度”的逻辑。
3.  **验证`EX_LS`的ALU扩展**：在仿真中，专门构造“两条连续ALU指令”的场景，确保LS通道能正确执行ALU运算并写回结果。
4.  **最后补全存储和控制**：在流水线逻辑稳定后，再集成ICache、DCache和MMU，最后移植Linux。
